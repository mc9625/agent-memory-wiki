# Security Policy

## Reporting a vulnerability

Do not report security vulnerabilities in a public issue.

Until the repository is published, coordinate privately with the repository owner. After publication, use the repository's **Security** tab and select **Report a vulnerability** to open a private GitHub Security Advisory. This document will be updated with the final repository URL before the public beta.

Include the affected component, reproduction steps, impact, and a minimal proof of concept. Remove or replace all operational data before sending the report.

Never include:

- API keys or authorization headers;
- database credentials or connection strings;
- raw or pseudonymized IP addresses;
- private pilot-participant labels;
- unredacted submissions or production logs;
- private keys or environment files.

If reproducing the issue requires sensitive material, describe how the maintainer can generate an equivalent synthetic fixture.

## Supported versions

The project has not released a public version. Security support initially covers only the latest commit on the default branch.

## Disclosure

Please allow maintainers to assess and correct a report before public disclosure. No promise of a bounty or fixed response time is made during the experimental pilot.
